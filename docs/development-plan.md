## 1. 엔진 기반

| 항목 | 구현 범위 |
|---|---|
| 빌드·모듈 | 프로젝트 생성 자동화, Debug/Release, Engine·Editor·실행 앱 책임 분리. 라이브러리/DLL 구성은 미정 |
| 엔진 구조 | World가 Actor를 소유하고 Actor가 Component를 소유. 생성·삭제·갱신·시작·종료와 참조 수명 명확화 |
| 루프·변환 | 입력 → 이동·충돌 → 카메라 → 렌더링. 로컬/월드 변환과 Quaternion 회전 |
| DX12 렌더러 | 기본 메시·깊이 렌더링, 셰이더·자원 업로드, Descriptor·Barrier·Fence와 자원 수명 관리 |
| Static Mesh·Material | 지형·보드·임시 탑승자 표시, 최소 메시 로딩, 기본 색·텍스처 |
| 라이팅 | Ambient + Directional Light, 단순 셰이딩. 그림자는 추가 범위; 다수 광원·CSM은 보류 |
| 장면·속성 | 배치·설정 편집, 저장·로드, 실행 후 초기 상태 복원. 속성은 직접 작성/수동 등록부터; 자동 UProperty 생성기는 보류 |
| 충돌 | 정적 지형, 이동 충돌체, Raycast·Sweep·필터·겹침 처리. 물리 라이브러리와 충돌체 형태는 미정 |
| 입력·카메라 | 이동 입력, 추적 카메라, 벽면 주행 중 자세 변화에 따른 시야 확인 |
| 진단 | 충돌체·접촉점·법선·속도·이동 상태 표시, Debug Layer·PIX, 필요 시 DRED |
| 실행·보존 | IDE 밖 실행·패키징, exe·PDB·소스 버전 보존과 CPU 덤프 분석 |
| 이후 확장 | Lua로 구역 진행·이벤트 작성. 스켈레탈·애니메이션·파티클·래그돌은 검증 이후 별도 판단 |

## 2. 기능 수직 검증 — 채택 전

로직으로 이동을 제어하고 충돌 질의로 제한하는 방식부터 검토한다. 임시 모델·최소 이동으로 실험한다.

| 항목 | 확인할 범위 |
|---|---|
| 충돌 질의 | 평지·경사·벽의 접촉 위치·법선·Sweep 결과가 맞는지 |
| 기본 이동 | 최소 가속·회전·정지, 접촉 유지·낙하. 드리프트 완성도 조정은 채택 후 |
| 벽 한 면 | 붙은 상태의 이동·자세 유지, 이탈 방향·속도 |
| 완만한 전환 | 바닥 → 벽 연결에서 표면 선택·충돌·속도·자세 전환 |
| 날카로운 경계 | 90도 경계의 실패 원인 조사. 성공은 필수 아님 |
| 반복 검증 | 속도·진입 방향·프레임 조건을 바꿔 비교, 카메라·입력의 일관성 확인 |

**결정:** 가능한 지형·조건과 남은 위험을 정리하고 채택·범위 축소·보류를 결정한다.

## 3. 채택 후 단계별 구현

| 단계 | 구현 범위 | 남길 결과물 |
|---|---|---|
| 1. 지상 보드 | 가속·회전·제동·드리프트, 작은 주행 구역 | 설정 수정·상태 확인·재시작이 가능한 독립 실행 빌드 |
| 2. 제한된 벽면 주행 | 지정 표면의 진입·주행·이탈·착지 | 지원 조건에서 반복 동작하고 실패 이유를 확인할 수 있는 빌드 |
| 3. 연속 주행 연구 | 바닥↔벽·벽↔벽 등 선택한 경계 확장 | 성공 범위·실패 조건 기록, 안정적인 기능만 통합 |

각 단계의 실행 결과물을 보존한다. 연구가 지연되면 3단계를 줄인다. 우산·공중 공격은 이번 범위에서 제외한다.
